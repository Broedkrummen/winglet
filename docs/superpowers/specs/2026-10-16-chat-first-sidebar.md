# Chat-first navigation

This supersedes the bottom navigation and boxed Home carousel in the earlier mobile-polish documents. The user requested a quiet default chat canvas, a lower and unboxed bot slot, recent conversations in a sidebar, Inbox at the top right, and separate Settings and Agent destinations. No subagents or PR review workflow were requested or used.

## References and interpretation

- [How We Designed Muse](https://introducing.muse.ai/) describes a main conversation with separate side chats and visible agent activity.
- [Claude Code desktop redesign](https://claude.com/resources/articles/claude-code-desktop-redesign) describes a sidebar collecting active and recent sessions. This is the verified redesign reference; no claim is made that a particular “version 3” announcement was found.
- Winglet uses these interaction principles rather than reproducing desktop tooling or a reference app's branding.

## Current behavior

- The default route is a blank composition canvas for the selected bot's main conversation. Its shared draft, model, attachment and microphone controls stay near the bottom. Sending transforms this canvas into the full conversation in place, preserving the same composer and keyboard instead of pushing another route. Previous messages appear with the new exchange, and normal older-history paging remains enabled. The actual main conversation and server context remain unchanged. Choosing Chat in navigation returns to the clean landing while preserving stored drafts and history. It does not create an empty server chat at startup.
- A transparent bot deck sits immediately above the composer, with neighboring pets visible and UI-thread drag/spring behavior. Card backgrounds, borders, orbit decorations and the central hero layout are removed. Pets are about 37% larger than the first sidebar iteration, with depth, a slight tilt and a controlled settling spring. Focusing the composer hides and disables all dock pages, commits the selected bot, and settles its pet from the measured dock slot onto the composer. Sending adds a small hop and keeps the pet perched beside the conversation. Dismissing an unused composer restores the dock. The pet and composer share the keyboard viewport, including on existing conversation routes. Message spacing reserves the pet's perch, reduced motion skips travel, and hidden deck pet loops pause. Memoized dock, pet and message-list components avoid unrelated parent renders.
- The deck starts with New chat, followed by the main bot, secondary bots and Add a bot. Ordinary main-bot input continues in its existing main conversation. New chat has the shared composer, bound only to the configured main bot and using a separate local draft. The first send creates its side chat and shows replies in place; later sends reuse that conversation. Attachments and model selection also resolve that new chat when they need a real server destination. Swiping or typing alone creates nothing. Creation is shared across overlapping controls, preserves the latest typed draft and can be retried after failure. Tapping the active New chat icon focuses its composer. Add a bot retains an explicit action to open the existing create/pair sheet.
- The landing owns the active dock page. Add a bot uses the same mounted chat shell and carousel; entering it, waiting, opening setup and returning cannot reset it to a bot through a carousel mount effect. Only an actual external bot selection resets action pages.
- Dock visibility is structural: after a send the conversation has no carousel subtree. While an unused composer is focused, the retained dock uses `display: none` and ignores zero-size hidden measurements, preserving its page and pet origin for cancellation. Animated opacity is not responsible for hiding it; a failed/reset animation cannot draw a second pet or dock over messages.
- Three dots at the top left open a left drawer. Inbox and its pending count sit at the top right. Conversation headers expose the same navigation, with their contextual chat menu preserved.
- A root-level navigation shell covers conversations and settings as well as the retained section routes. The bottom navigation and its hold-to-talk/quick-ask shortcut are removed; microphone recording remains in the shared composer. Existing sections now reserve only their bottom safe area.
- The sidebar groups Chat/New chat, history and Agent/Settings into separate rounded cards, with local title/bot search inside the history card. A subtle tinted glass surface and translucent cards preserve text contrast; reduced transparency uses solid surfaces. Pinned and recent conversations span bots, with All chats & archived below. Each chat has a three-dot menu and long-press access to the existing chat actions, including pin/archive/rename/delete for side chats; main chats retain their existing protections. Delete still requires confirmation. The footer bot selector is removed. Opening existing history selects its matching bot and chat and shows the full conversation. Sidebar New chat uses the existing creation action and prevents duplicate taps while pending.
- Settings and Appearance offer Automatic, Drawer and Pinned navigation. Automatic docks a full 280-point sidebar at widths of at least 1100; Drawer always uses the overlay. Pinned uses the full sidebar on large screens and a 64-point rail on phones. The rail has separate circular destinations, a rounded accent tile and edge marker for the active section, workspace dividers and an Inbox shortcut with a pending badge. Chat split layouts use the remaining content width, not the whole window.
- The drawer is 72% of the window width, capped at 340 points. It animates in, supports backdrop/close/Android Back/Escape dismissal and leftward swipe dismissal, and measures keyboard overlap so search and footer navigation stay usable. It shares the app window instead of opening a native modal. Closing removes its interaction layer immediately without waiting for an animation completion callback. Its keyboard wrapper is bounded to the drawer width so it cannot intercept outside taps. Reduced-motion settings apply to the drawer and bot deck. Locking immediately removes drawer/rail access and hides underlying content from interaction/accessibility; the lock cover is outside the navigation shell.
- Empty conversations no longer show a large avatar, suggestions or explanatory marketing text. Agent configuration, Updates, archive actions, approvals, message copy/reply and existing chat controls remain available through their existing routes.
