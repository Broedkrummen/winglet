# Herald — checkpoint history and restore sheet

Winglet's workspace checkpoints feature adapts the interaction design of Herald's
checkpoint sheet and its data handling. No Kotlin or Compose source was copied
verbatim; behaviour, information hierarchy, edge-case handling and user-facing
wording patterns were ported to Winglet's React Native UI and Python plugin, and the
data path was rebuilt against Hermes's real `tools/checkpoint_manager.py` instead of
Herald's dashboard JSON-RPC calls.

- Source: https://github.com/Giton22/herald
- Reviewed commit: `95ca999fa48c1c9de232fe499a174900f0d25272`
- Files studied and adapted:
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/Checkpoints.kt`
  - `shared/ui/src/commonMain/kotlin/dev/hermeskotlin/ui/chat/CheckpointsSheet.kt`
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/ChatSession.kt`
    (`checkpoints`, `checkpointDiff`, `restoreCheckpoint`)
  - `shared/ui/src/commonTest/kotlin/dev/hermeskotlin/ui/chat/CheckpointsControllerTest.kt`
  - `docs/screenshots/checkpoints.jpg`

Modifications: the checkpoint list/preview/restore contract is expressed as Winglet
HTTP routes and capability flags; previews are bounded and carry a revision token;
restore requires an owner signature, a matching revision and an idempotent operation
id; Hermes's `safe` restore and pre-rollback snapshot are surfaced; transcript
rewind (`history_removed` in the reference) is intentionally not claimed.

# Herald reuse notice — event replay

Winglet's resumable event stream (`plugin/event_replay.py` and
`app/src/features/event-replay/`) is an adaptation of the replay semantics in Herald, a separate
Kotlin Multiplatform client for Hermes. The code was rewritten for Winglet's Python plugin and
TypeScript/React Native app; no Kotlin source is copied verbatim, but the protocol decisions below
are derived from Herald's implementation and tests and this notice is included as required.

- Source: https://github.com/Giton22/herald
- Reviewed commit: `95ca999fa48c1c9de232fe499a174900f0d25272`
- Upstream files read and used as the behavioural reference:
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/EventReplay.kt`
  - `shared/core/src/commonTest/kotlin/dev/hermeskotlin/core/chat/EventReplayTest.kt`
  - `shared/core/src/commonTest/kotlin/dev/hermeskotlin/core/chat/ChatSessionResumeTest.kt`
  - `docs/ROADMAP.md` (the "exact event replay after reconnect" entry)
- Upstream licence: MIT (below).

## What was reused or adapted

- Monotonic per-stream `seq` stamped on every event, with a client cursor that only advances past
  events it has already applied, and the rule that an already-applied seq is skipped when a replay
  overlap hands it back.
- A stream `epoch` identifying the sequence space: a restart or a reset that counts anew must be
  refused rather than interpreted, and a `latest` below the client's cursor is treated as the same
  restart seen without an epoch.
- Refusing a replay when the retained window lost events (`truncated`), when sequence numbers have a
  hole, or when an event belongs to another scope; the caller then reloads authoritative state
  instead of guessing.
- `latest` may be ahead of the returned events because an event can be stamped between reading the
  window and reading the head; the client leaves those to the live stream.
- The client-side pattern of applying replayed events through the same reducer as live frames,
  dropping duplicates by seq, and keeping the transcript refetch as the fallback.
- The "reconnecting / waiting for network" presentation, adapted to Winglet's restrained sync chip
  instead of a chat-level spinner.

## Modifications for Winglet

- The stream is one durable SQLite journal per `(server, bot)` rather than an in-memory ring per
  runtime session, so a disconnect survives a plugin restart.
- Filtering is per device at replay time (role and chat ownership), with a server-issued watermark
  and an explicit `ok:false` reason plus a scoped snapshot endpoint; Herald's reply has no
  per-device authorization because its gateway serves one user.
- Sequence gaps caused by per-device filtering are normal in Winglet; the cursor advances to the
  server's watermark rather than to the last event, which Herald does not need.
- Oversized payloads are replaced by a `sync.hint` instead of being dropped entirely.

# Herald — structured execution notice

This notice covers material reused or adapted from Herald for Winglet's structured task activity
feature (`docs/agent-handoffs/execution.md`). Winglet's implementation is a TypeScript/React Native
and Python port, not a copy of Herald's Compose UI or Kotlin transport.

- **Source:** https://github.com/Giton22/herald.git
- **Reviewed snapshot:** `95ca999fa48c1c9de232fe499a174900f0d25272`
- **Upstream license:** MIT (full text below), Copyright (c) 2026 Giton22
- **Files studied and used:**
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/Subagents.kt`
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/Todo.kt`
  - `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/chat/ToolDetails.kt`
  - `shared/ui/src/commonMain/kotlin/dev/hermeskotlin/ui/chat/SubagentCard.kt`
  - `shared/ui/src/commonMain/kotlin/dev/hermeskotlin/ui/chat/TodoPanel.kt`
  - `shared/ui/src/commonMain/kotlin/dev/hermeskotlin/ui/chat/SessionControlPanel.kt`

## What was reused or adapted

- The task/subagent/plan status vocabulary (running, queued, completed, failed, interrupted →
  cancelled, unwatched, unknown) and the rule that an unknown end is never rendered as success.
- Bounded live activity: at most 24 lines kept upstream, 12 in Winglet; each line clipped, identical
  repeated lines collapsed, and subagent activity reconstructed from the stop hook's metadata-only
  `tool_call_history`.
- Plan tree flattening: items in list order under their parent, with a depth cap and a flat fallback
  for dangling parents or cycles.
- Subagent row projection: live subagents carry their id for control, finished ones do not; children
  are nested under their parent with a bounded depth; finished rows fold their detail.
- The calm card hierarchy: status disc + goal + meta line, one-line glance while collapsed, nested
  rule for children, expanded Activity/Result sections, and the "what went wrong" framing for failures.
- The progress panel's plan bar (done over non-cancelled steps), the live elapsed clock, and the
  in-place Stop control.

## Modifications

- Rewritten in TypeScript (`app/src/features/execution/`) and Python (`plugin/execution.py`) against
  Winglet's own transport: a messaging-platform plugin's observer hooks, `/api/task`, and namespaced
  `task.*` socket events. Herald's dashboard JSON-RPC session protocol is not used.
- Identity comes from Hermes's authoritative `turn_id`, `tool_call_id`, `child_subagent_id` and
  session ids rather than transcript positions.
- Tool arguments and results are not stored; Winglet keeps only a redacted preview and a bounded error
  line. Herald's `ToolDetails` formatting for arguments/outputs was studied but its payload retention
  was deliberately not adopted.
- Per-subagent cancellation is not exposed: the pinned Hermes offers no targetable child-cancel
  operation to a messaging adapter. Herald's per-subagent Stop therefore has no Winglet counterpart.
- Winglet's theme tokens, sheet, typography, icon set and accessibility conventions replace Herald's
  Compose design system. Status is always icon + label, not colour alone.
- A finished turn's strip lingers for 60 seconds so its outcome is discoverable; Herald keeps results
  in the transcript's delegation cards instead.

# Herald reuse notice: projects

Winglet's projects feature adapts behavior and small algorithms from the Herald reference app.
This notice covers the material first added by the projects feature PR. It is kept separate from
other feature notices so the orchestrator can consolidate credits later without losing the required
attribution.

- Upstream: https://github.com/Giton22/herald.git
- Reviewed snapshot: `95ca999fa48c1c9de232fe499a174900f0d25272`
- Local read-only review clone used: `C:\Users\vikas\AppData\Local\Temp\winglet-reference-review-20261023`
- Upstream license: MIT, Copyright (c) 2026 Giton22 (full text below)

## Files reviewed and what was reused

| Upstream file | Use in Winglet | Modifications |
| --- | --- | --- |
| `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/projects/ProjectIndex.kt` | The concept of a chat→project index and of excluding the unfiled "Home" bucket. | Reimplemented in TypeScript in `app/src/features/projects/logic.ts`. Winglet chats have stable ids, so Herald's compression-lineage lookup is not needed. Projects are Winglet SQLite rows, not gateway-discovered folders. |
| `shared/core/src/commonMain/kotlin/dev/hermeskotlin/core/projects/ProjectsApi.kt` | Project shape (id, label, position/count, user-made vs discovered), deterministic ordering, and the rule that a user-made project may be empty while discovered groupings are not shown. | Rewritten as `plugin/projects.py` and the Winglet project API.
